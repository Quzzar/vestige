# Native tipped wand verification · October 7

The isolated implementation extends the native foundation with all eight trusted tips, six-offering binding, cast-owned primary-outcome observers and bounded secondary tasks. It retains one exact source scroll variant and uses the same immutable spell, trait, cost, payment, continuation and cleanup runtime. Pure utility has caster-side options; no named-spell tip branches are introduced.

The final standalone source passes **137 unit tests**, **all 252 required native Minecraft tests**, and production build on Java 21 / Minecraft 1.21.1 / NeoForge 21.1.72. Fifteen added tip-world cases verify actual damage/healing echoes, current relationship guards, Fangs, bounded refraction, actual-payment rebates, no overheal rebate, utility success, safe/blocked backsteps, shared Conductive budget, friendly/resistance-safe repulsion, gradual recovery, owned preparation cleanup and six-input atomic binding. The complete suite retains the foundation's stacking, threads, wand payment/wear/recovery/recast tests and all prior native mechanics.

The same scoped source is integrated with the current shared-checkout features, preserving staffs, Whispering Shell, Crane Bag, preparation display and other agents' work. That combined source passes **152 unit tests** and **all 280 required Minecraft tests**, plus production build. The intentionally malformed Crane Bag storage fixture logs its expected load error and passes. Combined verification does not publish unrelated work in the wand pull request.

`wand-tip-compatibility.json` audits the **214** unshaped packaged spells, **30,065 supported tipped base/core combinations** and **81 pure utility spells**. It is eligibility evidence, not encounter balance or a guarantee for every future shaped variant. Every spell has Callous for every body; Emerald/Pearl/Ghast/Netherite provide broad utility choices. Mode plans, callbacks and bindings participate in capability detection. Existing source shaping and component seeds are retained exactly once; affinity checks the source before seeds.

The production export verifies **20 actual 16×16 PNGs** (seven bodies, eight tips, five threads) and 63 ordinary layered handheld models. The native palette capture verifies resource-loaded PNG dimensions/hashes and all appearances. JEI captures verify one recipe per untipped, Resonating, Steadfast utility and exact shaped-wand lookup at two GUI sizes. EMI's first acquisition refresh exposed concurrent index baking; the final adapter coalesces refresh requests until both the pinned EMI reload manager and asynchronous recipe worker report completion. Immutable structured comparison identities and cached recipe stacks avoid repeated scroll parsing/formatting in EMI hashing. JEI and standalone EMI each pass five native recipe lookup/capture cases. The combined JEI/EMI + Kithkyn client repeats all five; the neither-viewer + Kithkyn client receives the acquired exact source without loading optional APIs. Complete manifests and installed artifact details are recorded in `verification.json`. The combined bridge reports duplicate `jei:/` vanilla/tag recipe IDs; native wand lookups remain unique. Kithkyn's local LLM is disabled in disposable capture worlds.

Coefficients and durability are starting playtest values. Multiplayer transport is bounded but these client captures use integrated servers; no remote-session playtest or general modpack compatibility claim is made. Quartz, Redstone, Nautilus and Magma tips, repair/rebinding and encounter balance remain later work. Matching client/server builds are required for ritual protocol 5 and the version-1 wand display payload.

The combined jar is installed in **Prism → Kithkyn Testing**, SHA-256 `ab9ef827eb60c7c0e10a92681d01e771f73a008a4298ddeabc1ed437bcc5518f`. The prior jar is backed up outside `mods`; `installation.json` records its path and hash. Minecraft must restart to load the replacement. The isolated publication artifact has its own distinct hash and excludes unrelated shared-checkout work.

Earlier incomplete/closed captures are not counted as successes. Initial EMI refresh exposed concurrent comparison changes during asynchronous baking and was corrected before the verified runs. A development-only no-viewer diagnostic briefly referenced JEI, and was corrected with optional-class and null-screen guards before the final passing run. These guards do not alter normal gameplay.
