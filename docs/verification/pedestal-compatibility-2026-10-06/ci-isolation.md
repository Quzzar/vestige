# Pedestal release CI: existing cleanup-test isolation

The compatibility release's focused tests passed, but GitHub's full **206-test** suite failed twice in the existing orphan cleanup assertion. A full local reproduction identified the **same Stone Button UUID** before temporary blocks were placed and at the failure. The test was counting pre-existing loot as a new orphan cleanup drop. The button's original source was not established; no temporary block produced that entity during the measured interval.

A minimal regression deliberately places an unrelated Stone Button in the search area first. The old empty-area assertion fails on this single test. The fixed test snapshots existing entity IDs and item/component/count state, rejects any new entity or increased stack, checks that the unrelated item survives, then discards its own fixture. Log/leaves/water removal and no-spread checks remain. No gameplay or recipe code changes. The installed exact-tested compatibility candidate stays unchanged.

[Results and source hashes](ci-isolation.json) and [log excerpts](ci-isolation-results.txt) retain the original failure, minimal red/green checks and broad follow-up. All **107 unit tests** pass. The full local diagnostic run also encountered an existing column-cap assertion; the full run after the cleanup fix passed **205 of 206** tests, with an existing water-immersion assertion failing. These broad-run failures are recorded, not represented as passing tests. The final GitHub check remains a separate verification step. All temporary diagnostic instrumentation was removed from source.
