# Held spell preparation verification · October 7, 2026

The review build adds one held-item draw-back for scrolls, wands and staffs alongside the existing preparation bar. Its private version-2 payload routes an opaque source identity and reserved hand without spell/knowledge facts. The runtime and saved items keep their existing rules.

A frozen copy of the concurrently edited checkout passed production build, all **173 unit tests**, **55 required Minecraft behavior tests**, the Kithkyn compatibility check and both staff authoring checks. The world filter covers preparation, wands, staffs, native player mana and item mana. The added world test verifies three real casting sources, both reserved hands, rejection of unrelated cast identities, staff/scroll key separation and cancellation without mana spending. Source hashes, artifact hash, native checks and compressed logs are in `verification.json` and this directory.

[Native footage and stills](../../art/held-spell-preparation/README.md) record **213 actual framebuffers**, seven cases and two display/GUI sizes. Release costs are 42 mana/one scroll, 36 mana/one wand wear, and 42 mana/one staff wear; midway scroll cancellation leaves all resources intact. The wand's core extends the source's 40-tick preparation to 50 ticks. Every case includes charge frames matching the private held-source snapshot and registered client extension; end frames show cleared progress/source metadata.

Inspection corrected an overly close scroll draw, a capture-only 40-tick assumption for the 50-tick wand, and a left-hand staff angle. Final frames and a decoded demo frame were visually inspected. Third-person poses and hold-to-release controls are outside this presentation change. The native client uses an integrated server; remote appearance and the unrelated full world suite were not rechecked. The tested artifact is staged at `build/held-spell-preparation-review/libs/vestige-0.1.0.jar`; no running game profile was replaced.
