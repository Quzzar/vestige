# Map APIs for Standing Stones

**Researched and rechecked October 6, 2026.** Target: Minecraft 1.21.1, NeoForge 21.1.72, Java 21; the Kithkyn Testing profile uses NeoForge 21.1.248. The original request was clickable Standing Stones on a map alongside a list. The owner subsequently selected a native list-only menu, with terrain/Atlas and Waystones compatibility deferred to optional future work or an addon. The earlier feasibility evidence below remains research, not the current UI contract. Findings below distinguish published compatibility, inspected source and release jars, and inferred integration possibilities. No third-party code or art has been copied into Vestige, and this research adds no map dependency.

## Feasibility at a glance

An Atlas-style terrain map is practical. **Surveyor is the real backend library behind Antique Atlas 4**, but its advertised NeoForge support uses Connector and Forgified Fabric API. Native Antique Atlas 8.0.1 and Map Atlases offer other integration paths; none of the inspected public APIs provides a ready-made, stable Standing Stone destination picker. Keep Vestige's own list selection and travel validation; a future optional map view could supply terrain from a separately installed provider. These are feasibility findings, not an implemented terrain adapter or a new mandatory dependency. [Surveyor's official description](https://modrinth.com/mod/surveyor), [Antique Atlas 4's official API notes](https://modrinth.com/mod/antique-atlas-4).

## Antique Atlas, original project

[Antique Atlas's official listing](https://www.curseforge.com/minecraft/mc-mods/antique-atlas) includes a [1.21.1 NeoForge 8.0.1 release](https://www.curseforge.com/minecraft/mc-mods/antique-atlas/files/6849155), published August 5, 2025. This establishes a published native-loader candidate. The old [API wiki](https://github.com/AntiqueAtlasTeam/AntiqueAtlas/wiki/API), edited in May 2021 and describing API v3, is historical evidence rather than a verified contract for this release.

Inspected port source: [`Stereowalker/AntiqueAtlas`, revision `5b8740d17576872edee8d019d595ecb4fca07b46`](https://github.com/Stereowalker/AntiqueAtlas/tree/5b8740d17576872edee8d019d595ecb4fca07b46), branch `1.21`. `hunternif.mc.api.AtlasAPI`, `MarkerAPI` and `client.AtlasClientAPI` expose map/marker operations. Marker operations add/remove ordinary and global markers. `ClientTileAPI.getTiles(...)` supplies a `TileRenderIterator`, so low-level tile access exists. [Pinned client tile API](https://github.com/Stereowalker/AntiqueAtlas/blob/5b8740d17576872edee8d019d595ecb4fca07b46/src/main/java/hunternif/mc/api/client/ClientTileAPI.java).

The **published NeoForge jar was independently inspected** through its [Curse Maven artifact](https://cursemaven.com/curse/maven/antique-atlas-227795/6849155/antique-atlas-227795-6849155.jar). SHA-256: `b5b406b7b48fbdd68e66160a24145fc399f21e39f9f391120bb172e8180e45fc`. Its metadata declares Minecraft `[1.21,1.22)`, NeoForge `[21.0.0-beta,)` and UnionLib `[12.0.18,12.1.0)`. Those declared ranges admit both our loader versions; actual launch compatibility has not been tested. Compiled signatures confirm the APIs above. **`MarkerClickedCallback` is an empty interface in this release**, not a usable event. `GuiAtlas` has private hovered-marker state and private world/screen transforms; opening its screen is different from embedding a supported destination-selection component.

The port source builds against Forge 52.1.0, so source identity alone still cannot establish complete parity with the NeoForge jar. A custom tile renderer or invasive screen integration would need a separate prototype. Source code is GPL v3-or-later and textures CC BY-NC-SA 3.0 under the [pinned original license](https://github.com/Stereowalker/AntiqueAtlas/blob/5b8740d17576872edee8d019d595ecb4fca07b46/LICENSE); calling an API and copying its implementation/art are separate choices.

## Antique Atlas 4 and Surveyor

[Antique Atlas 4's official page](https://modrinth.com/mod/antique-atlas-4) describes an Atlas frontend for Surveyor, an unstable API, `AtlasRenderer.registerOverlay()`, and Surveyor landmarks. On (Neo)Forge it explicitly calls for Connector and FFAPI. This is a materially different dependency route from a native NeoForge library.

The refresh checked the actual `1.21` branches, superseding the earlier inspection of Surveyor's `1.20` default branch:

- **AA4 3.1.2+1.21:** [published release](https://modrinth.com/mod/antique-atlas-4/version/2sDsTAId), [source `1821a06b0ad40b12fc1bf9943baf307fc9ed9fc3`](https://github.com/sleepingdragoninn/antique-atlas/tree/1821a06b0ad40b12fc1bf9943baf307fc9ed9fc3). Published January 5, 2026; release jar SHA-256 `868cca6e9bcee4e439e863cbb053fc1a9c0ea10e405c5d6062b2021042ff08ac`.
- **Surveyor 1.2.4+1.21:** [published release](https://modrinth.com/mod/surveyor/version/egJBsDTn), [source `22e24e092b22249b3601746bfaf29c838ad78a1d`](https://github.com/sleepingdragoninn/surveyor/tree/22e24e092b22249b3601746bfaf29c838ad78a1d). Published May 10, 2026; release jar SHA-256 `4c4534517021e5b7212346e25510123944558e5b0fcf1d605189548b6811a6a0`.

Both release jars were downloaded only for metadata/API inspection and checked against Modrinth's published SHA-512. Both declare `connector:placeholder = true` and require Connector plus `fabric_api` in their NeoForge metadata. AA4 requires Surveyor at least `1.1.2+1.21` and Fabric API at least `0.115.6+1.21.1`; Surveyor declares Fabric API at least `0.104.0+1.21.1`. The compatible FFAPI/Connector releases and our precise baseline have not been launched together. [Pinned AA4 loader declaration](https://github.com/sleepingdragoninn/antique-atlas/blob/1821a06b0ad40b12fc1bf9943baf307fc9ed9fc3/src/main/resources/META-INF/neoforge.mods.toml), [pinned Surveyor declaration](https://github.com/sleepingdragoninn/surveyor/blob/22e24e092b22249b3601746bfaf29c838ad78a1d/src/main/resources/META-INF/neoforge.mods.toml).

Surveyor supplies terrain, exploration, structures and landmarks rather than a UI widget. The inspected 1.21 API exposes `SurveyorClient.tryGetSummary(dimension)`, `WorldSummary.terrain()` and `WorldTerrain.get(chunkPos)`; absent terrain/summary is possible. A frontend can consume explored map data independently of AA4. [Client API](https://github.com/sleepingdragoninn/surveyor/blob/22e24e092b22249b3601746bfaf29c838ad78a1d/src/main/java/folk/sisby/surveyor/client/SurveyorClient.java), [world summary](https://github.com/sleepingdragoninn/surveyor/blob/22e24e092b22249b3601746bfaf29c838ad78a1d/src/main/java/folk/sisby/surveyor/WorldSummary.java), [terrain API](https://github.com/sleepingdragoninn/surveyor/blob/22e24e092b22249b3601746bfaf29c838ad78a1d/src/main/java/folk/sisby/surveyor/terrain/WorldTerrain.java).

AA4's `AtlasOverlay` supplies initialization/render callbacks, confirmed in the published jar. **It has no marker-click callback**. `onScreenInit` can access the concrete screen, but using that to add controls or override interaction is custom screen integration, not a verified stable teleport-picker contract. AA4's own `mouseClicked` handles waypoint editing/deletion and map dragging. [Overlay interface](https://github.com/sleepingdragoninn/antique-atlas/blob/1821a06b0ad40b12fc1bf9943baf307fc9ed9fc3/src/main/java/folk/sisby/antique_atlas/gui/AtlasOverlay.java), [screen implementation](https://github.com/sleepingdragoninn/antique-atlas/blob/1821a06b0ad40b12fc1bf9943baf307fc9ed9fc3/src/main/java/folk/sisby/antique_atlas/gui/AtlasScreen.java).

AA4 code is LGPL-3.0-or-later; its textures are CC BY-NC-SA 4.0. Surveyor is LGPL-3.0-or-later. These licenses do not establish API stability. [AA4 license](https://github.com/sleepingdragoninn/antique-atlas/blob/1821a06b0ad40b12fc1bf9943baf307fc9ed9fc3/LICENSE), [Surveyor license](https://github.com/sleepingdragoninn/surveyor/blob/22e24e092b22249b3601746bfaf29c838ad78a1d/LICENSE).

## Map Atlases for Forge/NeoForge

Inspected [`MehVahdJukaar/mapatlases-neoforge`, revision `b55167c9d527c88d5f542256ddb0eee996ade205`](https://github.com/MehVahdJukaar/mapatlases-neoforge/tree/b55167c9d527c88d5f542256ddb0eee996ade205), branch `1.21.1`. Its `MapAtlasesApi` exposes `isAtlas`, `getActiveAtlas(Player)`, `getMapId(...)` and `getMapDataAt(ItemStack, Level, double, double)`, returning vanilla `MapItemSavedData` for available atlas maps. The client API handles decoration scaling/text. The inspected `AtlasOverviewScreen` is coupled to atlas, lectern and pin-editing behavior rather than exposing a verified standalone destination-selection component.

The refreshed pinned properties identify **1.21-7.0.1**, Minecraft 1.21.1, compile loader **21.1.248**, Moonlight **1.21.1-3.6.10** minimum and CodecUI **1.21.1-1.4.5** as a build dependency. This replaces the previous note's 6.7.1/older Moonlight values. The [published 7.0.1 NeoForge release](https://modrinth.com/mod/map-atlases-forge/version/ecuMnNO4), September 26, 2026, was also inspected: SHA-256 `df61ef92809ce4627a5e4bd395d930997e0d3b4a0b9fa91d0beed5c23d127d6f`. Its public compiled API matches the methods listed above; metadata requires Minecraft exactly 1.21.1 and Moonlight at least 3.6.10, while declaring `*` for NeoForge. **21.1.248 is the compile version, not a declared minimum.** Compatibility with our 21.1.72 baseline still needs a real launch test. [Pinned properties](https://github.com/MehVahdJukaar/mapatlases-neoforge/blob/b55167c9d527c88d5f542256ddb0eee996ade205/gradle.properties), [loader declaration](https://github.com/MehVahdJukaar/mapatlases-neoforge/blob/b55167c9d527c88d5f542256ddb0eee996ade205/neoforge/src/main/resources/META-INF/neoforge.mods.toml).

`getMapDataAt` returns null when the atlas/map is unavailable and uses the selected map slice. It supplies existing vanilla map data rather than surveying arbitrary terrain for us. The client API contains two decoration-scale helpers, not marker-selection events or a reusable map widget. [Public map-data API](https://github.com/MehVahdJukaar/mapatlases-neoforge/blob/b55167c9d527c88d5f542256ddb0eee996ade205/common/src/main/java/pepjebs/mapatlases/api/MapAtlasesApi.java), [client API](https://github.com/MehVahdJukaar/mapatlases-neoforge/blob/b55167c9d527c88d5f542256ddb0eee996ade205/common/src/main/java/pepjebs/mapatlases/api/MapAtlasesClientApi.java). The [native fork license](https://github.com/MehVahdJukaar/mapatlases-neoforge/blob/b55167c9d527c88d5f542256ddb0eee996ade205/LICENSE) is GPL-3.0; it differs from the original Fabric project's listing.

**Inference:** the public map-data API could feed a terrain background into Vestige's own picker when the player has the appropriate atlas data. This would preserve Vestige's server-owned destination logic and avoid dependence on an unrelated screen's internals. It remains an unimplemented hypothesis, subject to version compatibility, coverage/fog rules and client-only dependency handling.

## Atlas API is a different kind of atlas

[Iron's Atlas API](https://modrinth.com/mod/atlas-api) provides runtime texture atlases and data-driven sprites. It does not provide geographic maps or a waypoint picker. Its name alone should not be treated as evidence for an Atlas map integration.

## Earlier implementation recommendation (superseded menu)

Keep Standing Stone keys, persistent membership, selection validation and teleportation native to Vestige. The first screen plots actual endpoint coordinates on a schematic grid, with synchronized pins/list and a single Travel action. It requires no map mod. An optional terrain background can follow once a specific provider/version is verified. Published loader support or a marker API alone does not establish a usable, stable embeddable teleport UI.

**Recommendation from this refresh:** retain that native picker. Prototype an optional Map Atlases terrain provider first for a native NeoForge route; Surveyor is the stronger reusable exploration backend if the owner accepts the Connector/FFAPI stack. Either route needs a client-only adapter, bounded visible-tile reads, dimension/coverage handling and original Vestige presentation assets. Displayed terrain should never choose network membership, grant teleport authority, charge resources or bypass server validation. Preserve the schematic fallback when the provider is absent or has no map coverage. None of those adapters was implemented or game-tested during this source/API investigation.

For layout research, reviewed [Tripadvisor](https://mobbin.com/screens/5d6f6163-5f61-41de-9009-2f634676b1c0), [Mindtrip](https://mobbin.com/screens/9c1aab4b-3752-405b-af7b-ea328fc9ebb9) and [GetYourGuide](https://mobbin.com/screens/7d8762de-2deb-4393-8667-dd8751d3b206) map/list references. The retained interaction is shared selection and one destination action, expressed with Minecraft's native font, buttons and rune signature. Those examples are design references, not Minecraft API evidence or copied assets.

## Accepted scope after the map review

The October 6 owner decision is a clean native list, in-menu current-stone naming and the four-rune signature at the bottom. The previous schematic map and its zoom controls are removed from the active screen. The base mod gains no map dependency. Antique Atlas and Waystones compatibility are desired future work; an optional addon may carry the larger integration. Candidate marker/terrain APIs above are evidence for that later investigation, not shipped adapters. Waystones interoperation has no selected semantics or verified API yet. See [Standing Stones](../design/standing-stones.md#optional-compatibility-deferred).
